# MemorySearch 本机使用 SOP

现版代码集中在同一个项目目录。日常从桌面的 MemorySearch 日常快捷入口启动。

> 通用公开版：<CODE_CHECKOUT> 指本机代码 checkout；<MEDIA_ROOT> 是本机原件目录；<INDEX_ROOT> 是其中的 .memorysearch-index。媒体实际位置只记在本机配置，不上传 Git。

## 每日使用，只需这几步

- 在 Finder 打开桌面已配置的 MemorySearch 日常快捷入口，或 <CODE_CHECKOUT>。
- 首次切换版本时，先关闭旧窗口，双击旧入口的 Stop，等待停止。
- 双击 `MemorySearch-Open.command`，等待本机窗口出现。
- 选“照片”“视频内部画面”或“照片＋视频”，输入中文；设置“结果数量”（1–50，默认 10），再点“查找”。

{{START_FLOW}}

## 常用入口

| 脚本 | 用途 |
| --- | --- |
| MemorySearch-Open.command | 启动或复用本机服务，并打开窗口 |
| MemorySearch-Status.command | 查看就绪状态和匿名汇总 |
| MemorySearch-Stop.command | 停止此入口拥有的服务；不强杀其他实例 |

已迁移并校验的索引会直接使用，无需重新建索引。关闭搜索窗口不会停止常驻模型；不用时再运行 Stop。

# 两个位置怎样连接

## 代码文件夹：可以进 Git

<CODE_CHECKOUT> 保存源代码、启动入口、依赖版本和本指南。`memorysearch_local` 是现版应用；仓库原有历史工作流保留，不作为此入口的日常命令。

`runtime` 在同一代码文件夹内，保存本机 Python、模型、工具、配置和运行状态；它已被 Git 忽略。

## 原件文件夹：不进 Git

<MEDIA_ROOT> 保存原有照片和视频。专用 <INDEX_ROOT> 是它的隐藏子目录 `.memorysearch-index`，只放索引、必要缩略图、就绪标记及维护回退快照。

原件根已有的 `index.json` 不会被覆盖。新索引目录被扫描器明确排除，不能把缩略图再当原件。

## 连接靠配置，不靠搬动原件

`runtime/local-config.json` 明确填写 `MEDIA_ROOT` 和 `INDEX_ROOT`。数据库保留原件的相对位置；模型与运行资源由同一配置指向 `runtime`。

> 代码更新不会自动搬动原件。索引迁移只复制本机事务快照；原索引保留。两处都不需要为了使用而建立新的私人远端。

索引目录权限为 0700，索引文件为 0600；本机配置也为 0600。不要手动将它们加入 Git、云盘或共享文件夹。

# 首次准备与安装

## 已完成本机配置时

直接运行 `MemorySearch-Install.command`。它校验固定模型文件的 SHA256、Python 导入和本机工具，并编译原生窗口；不会自动下载或开始扫描图库。

## 换一台电脑或全新 checkout

先按 `docs/MemorySearch-SETUP.md` 准备独立 Python 环境、官方固定版本模型及 FFmpeg。版本清单和模型来源均随代码保存，权重和环境不上传仓库。

复制 `memorysearch_local/local-config.example.json` 到 `runtime/local-config.json`，在本机填入实际路径，并限制为仅当前用户可读。不要把样板中的占位符当真实目录。

## 先检查存储，再迁移

运行 `MemorySearch-Check-Storage.command`。目录必须是真实本机目录，不能是软链接、Finder 替身、网络挂载或云端占位文件。

还要确认桌面或目标文件夹没有 iCloud、第三方云盘或跨设备同步。系统属性缺失不等于没有同步。

> 如果结果是 blocked，先继续用原入口。不要把 NO_SYNC_CONFIRMED 改成 true 来绕过未知状态；它只记录已经确认的事实。

准备不完整时会显示可读错误，程序不会猜测另一个媒体目录，也不会自动重建全库。

# 迁移已有索引

## 一次性维护，由本机完成

先确认旧索引已经完成、没有写入任务，且目标存储通过同步检查。在本机配置中填写 `SOURCE_INDEX_ROOT`；此字段只存在于被忽略的私人配置。

运行 `MemorySearch-Migrate-Index.command`。它在独立禁网进程中使用 SQLite 事务备份，兼容已有 WAL，不是直接复制活动数据库主文件。

它校验结构、固定模型空间、向量长度、引用一致性及迁移前后汇总。只复制索引引用的必要缩略图；不复制模型、虚拟环境、历史实验、原始日志或临时缓存。

## 确认就绪后才切换

- 核对迁移通过、原库保留、汇总一致及就绪标记。
- 确认没有正在执行的用户请求，停止旧服务。
- 从新代码文件夹运行 Open，检查状态和本机搜索。
- 新入口确认可用后，再让桌面快捷入口指向它。

> 目标目录已经存在时，迁移入口拒绝覆盖。失败时只清理本次新建的不完整目标，不删除原库，也不碰原件根的 index.json。

迁移完成不等于搜索准确度达标。未知标签、普通视频误报及动作理解的限制仍需如实保留。

# 照片：先候选，后分组

输入一个可见目标，例如“红色帐篷”，选择“照片”，点击“查找”。这是通用示例，不代表你的图库一定含有这个目标。

先显示本次所设数量以内的原始候选，照片核验随后在本机运行。核验支持的项移到前面，其余原候选保留在折叠区，成员不被删除。

{{PHOTO_GROUPS}}

点击“展开其他原始候选”查看未确认或未获支持的项；点击“恢复原始排序”查看原搜索顺序，再用“查看核验分组”返回分组视图。

点击“查看原图”打开本机原图窗口。数量越大，图片载入和照片核验可能越慢，超时仍回到完整原始候选。模型可能认错或拒绝真实目标；分组不是正确性保证，折叠中的真项仍算首屏遗漏。

> 核验不可用、失败或超时会恢复原始候选和顺序。不要把正在核验、UNKNOWN 或未获支持理解成“图里一定没有”。

# 视频：搜索和播放

选择“视频内部画面”，输入清楚的中文对象或场景，例如“鸭子”，点击“查找”。本入口沿用原生视频检索。混合模式同时召回两类，视频不参加照片核验。

{{VIDEO_SEARCH}}

每条返回对应原视频文件。目标在中间或后段出现也应按整个文件判断；候选缩略图不能证明目标在整段中不存在。

点击“播放视频”，在窗口内播放；拖动播放器进度条查看其他时段。搜索不会剪改或重写原视频。

## 结果的实际边界

相似背景可能产生无关视频；动作方向、细小物体、短暂场景可能漏检。没有独立证据时，不把相似度或少量帧当作精确答案。

视频也按“结果数量”返回，最多 50，实际不足时不补数；重新打开窗口会保留数量，不承诺返回项都准确。本次目录整理与照片分组不代表视频质量已经通过发布验收。

# 安全增加新素材

将新增原件放入原来的 <MEDIA_ROOT>。不要移动或编辑隐藏索引目录；不要为了新增几件素材重建全库。

## 先预览变化

双击 `MemorySearch-Incremental.command`，默认只读 dry run。它只统计新增、改动、未变和缺失，不解码原件、不写索引、不输出文件清单。

## 明确执行时

先停止此版本服务，在终端进入代码文件夹，运行 `./MemorySearch-Incremental.command --apply`。有活动实例或端口归属不清时会拒绝执行。

实际更新仍在禁网进程中进行，保留一个事务回退快照。未变化文件跳过，新增或改动文件使用原模型处理；缺失文件只在索引中标记，不删除原件。

完成后查看匿名汇总，再双击 Open。若处理中断，保留当前状态，由维护流程检查；不要手动删数据库、WAL 或锁文件来“解锁”。

> 初次切换尚未完成时，不能把新入口的增量命令用于旧入口的私人目录。先完成迁移与就绪核查。

是否增加了可搜索项，以实际增量汇总为准。这里只读预览成功，不能冒充私人素材已经更新成功。

# 停止、故障与回退

| 现象 | 应对 |
| --- | --- |
| 正在准备模型 | 查看 Status；首次加载较慢，不重复开第二个服务 |
| 端口已占用 | 保留现有实例；确认归属与空闲后用它自己的 Stop |
| config_missing / runtime_missing | 检查本机配置、固定资源与 Install；不扫描别的目录 |
| index_not_ready | 迁移或校验尚未完成；继续原入口 |
| sync_unconfirmed | 暂不写入索引；核实同步状态，不关闭整机连接 |
| 照片核验故障 | 自动显示原候选；必要时执行照片核验回退 |

## 可撤销的照片回退

`MemorySearch-Rollback-Photo.command` 仅在本机关闭随后请求的照片核验，恢复原搜索展示；不改模型、原件、排序算法或索引。服务与原候选仍可使用。

## 整体切换失败

运行 MemorySearch-Rollback.command 可按本机已保存的回退记录停止新服务、恢复上一服务和桌面入口。也可用新入口自己的 Stop 停止新服务，再打开保留的上一入口。原数据库未删除；不要把新旧服务同时开在同一端口。切换前本机应保留已验证的旧启动位置和回退说明。

未切换的安装不需要“回滚生产”。代码已写入、下次可用和当前实例已加载，是三个不同状态。

# 离线复验与数据隔离

## 两种复验分开看

`MemorySearch-Verify.command` 不加载模型，检查目录排除、未知状态、成员保全、启动互斥和接口契约。

`MemorySearch-Verify.command --live` 生成专用合成照片和视频，通过真实启动入口运行固定模型、原生窗口、播放和拖动；还检查禁外连、事务备份、增量预览和停止恢复。

该实测使用 CPU，不占用常用实例的 GPU。照片核验的分组/回退另做契约检查；这里未运行照片视觉模型时，会明确记录 `photo_model_executed=false`，不能称完整准确率验收。

## 哪些东西进入 Git

只提交必要源代码、已许可支持代码、固定清单、配置样板和本文档。`runtime`、本机配置、数据库、缩略图、原件、缓存、模型和运行记录一律排除。

## 发布前仍需确认

- 真实目标目录不被同步，私人事务快照校验通过。
- 常规入口已切换并空闲运行，回退入口可用。
- 照片与视频质量、唯一真项、未知和真实 UI 延迟分别计分。

> 合成集通过只证明工程链路能跑，不证明私人库验收通过。未核实的步骤必须保留为未核实，不能用进程活动代替结果。
